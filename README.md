# 寶隆客戶詢問與案件管理 Demo

可操作的繁體中文展示系統，紅黑視覺，資料與人名均為虛構。包含營運總覽、客戶詢問與門市指派、案件看板、拜訪紀錄、客戶洽談、客戶挽回分析、建案總覽與營運報表。

展示網址：[GitHub Pages](https://fci1007-design.github.io/baolong-case-management-demo/)。

原始碼儲存庫：[fci1007-design/baolong-case-management-demo](https://github.com/fci1007-design/baolong-case-management-demo)已公開，持有連結即可查看程式碼；Pages 展示網站公開，本機啟動器仍可使用。原 Sites 僅保留歷史紀錄。

## 產品類別與進度

頁面上方可切換全部類別、廚房櫥櫃、晶石板或酒品。範圍套用至詢問、洽談、案件、拜訪、建案及報表；選擇的類別會保存在目前瀏覽器。

| 類別 | 進行中流程 | 完成狀態 | 主要資料 |
| --- | --- | --- | --- |
| 廚房櫥櫃 | 需求確認 → 丈量提案 → 報價議價 → 待簽約 | 已成交 | 原有案件與建案戶別 |
| 晶石板 | 需求確認 → 選材／尺寸確認 → 報價確認 → 備貨交貨 | 交貨結案 | 品名、規格／花色、片數、使用位置 |
| 酒品 | 拜訪洽談 → 需求詢價 → 報價確認 → 訂單確認 | 交貨結案 | 品項、產品規格、瓶／箱數量、採購用途 |

三類均可記錄未成交／流失原因。晶石板以選材、牆面尺寸、供料片數與交貨為主要追蹤內容；酒品則以採購及交貨為主。這些流程是本輪 Demo 設計，並非已核定的正式營運或會計規則。

- 新增案件可選產品類別，階段、案件類型與產品欄位隨之切換。產品資料可在案件明細編輯，案件總金額由業務填寫，不依片數或瓶／箱數自動推算。
- 晶石板及酒品各新增 12 件模擬案件，包含進行中、交貨結案與未成交情境，也有尚未立案的洽談、詢問、拜訪及待辦。原 30 件櫥櫃案件保留。
- 既有瀏覽器資料不會重設：原紀錄預設為廚房櫥櫃，兩類新範例以固定識別碼補入一次；原備註、進度與日期保留。
- 同一建案／戶別可有櫥櫃及晶石板案件，點選戶別可分別查看。晶石板片數與金額按案件計一次，不因關聯多戶重複加總。
- 酒品的瓶與箱分開彙總，不自動換算；規格可自行填寫每箱瓶數。酒品案件不使用建案戶別。
- 報表新增類別彙總，CSV 依產品類別及單位輸出；晶石板片數、酒品瓶數及酒品箱數各有獨立欄位。需求數量按目前非流失案件彙總。
- 展示統計以櫥櫃「已成交」、晶石板／酒品「交貨結案」列為完成，畫面使用「成交／結案」標籤；金額每案計一次。

## 執行

雙擊 `start-demo.command`，或在本目錄執行 `python3 serve.py --open`。不需要 npm 安裝；所有圖示、圖表、程式及樣式均為本機資產。

## 展示路線

1. 營運總覽 → 點開待聯絡客戶詢問 → 指派門市、記錄聯絡、轉為案件。
2. 案件看板 → 開案件 → 新增拜訪紀錄、照片、下一步 → 變更階段並查看最後更新日期。
   可先選「晶石板」建立 60 片牆面材料案件，再選「酒品」查看採購與交貨進度。
3. 客戶洽談 → 尚未立案的洽談 → 新增拜訪或轉為案件，保留歷史。
4. 建案總覽 → 戶別進度 → 一次新增多戶拜訪。
5. 客戶挽回分析 → 查看流失風險與處理紀錄 → 確認已成交案件的挽回結果。
6. 營運報表 → 切換門市與期間、匯出 CSV。

操作保存在目前瀏覽器，重新整理仍可接續；設定內可還原展示資料。不同網址、連接埠或瀏覽器各自保存展示資料，不會共享操作。

## 架構與展示假設

- `dist/data.js`：模擬資料與基礎字典。
- `dist/products.js`：產品類別、進度、拜訪目的、產品欄位驗證及模擬轉錄範本的單一來源。
- `dist/app.js`：狀態保存、共用計算、畫面、表單及互動。
- `dist/styles.css`：紅黑配色、柔和層次與 RWD。
- `dist/index.html`：無建置步驟的靜態入口。
- `serve.py` / `start-demo.command`：本機啟動。
- 展示採 4 小時首次聯絡期限；不是寶隆已裁定的業務規則。
- 角色只切換模擬視角。資料不經伺服器保存，不適合輸入真實個資。
- 官網、LINE、出圖、報價、簽認事件皆為展示資料；語音按鈕填入可編輯的模擬轉錄文字，介面明確標示。
- 模擬報表由同一份狀態計算；挽回結果只計經確認且案件仍成交的案件，建案金額每案件計一次。
- 本版不含正式登入、後端權限、外部介接、GPS、考勤、行程排程或對屋主發訊。

## 設計

主色紅色與黑色；內容底 `#F6F7F9`、白色 `#FFFFFF`。保留紅黑導覽與功能按鈕，移除宣傳標語、大型裝飾區與鼓動式文案。主要內文與表格約 16 px，標題 19–29 px，輔助標籤 14–15 px；常用文字採 `#202630`、`#505967` 等深色。手機以折疊導覽與直式案件卡呈現。

## 案件最後更新日期

- 卡片、列表與案件明細均顯示「最後更新日期」，使用 `statusChangedAt`，代表目前案件狀態生效的時間，顯示台北時間至分鐘。
- 新案件建立時記錄初始狀態時間；實際變更狀態時更新。新增拜訪、修改下一步或移交業務不改寫狀態時間。
- `updatedAt` 仍保存一般資料異動，與狀態時間分開；沒有變更狀態時，不會因重新選取同一狀態而刷新日期。
- 舊的本機展示資料保留原內容：先依目前狀態相符的歷程補入，成交案件其次使用原成交時間，其餘使用初始建立時間；不以拜訪更新日期或載入當下時間充當狀態時間。

## 發布與交接

- GitHub Actions workflow：`.github/workflows/pages.yml`，只將 `dist/` 上傳為 Pages artifact，不發布 README、交接、啟動器或歷史 Sites 設定。
- 推送 main 的 `dist/**` 或 workflow 本身變更時自動發布；亦可於 Actions 手動執行。純文件提交不觸發重發。
- 使用 GitHub 內建 token 與 OIDC，不需新增密鑰或環境變數。
- 發布來源及實際結果見 `DEPLOY.md`；最新狀態見 `CHAT_HANDOFF.md`。
